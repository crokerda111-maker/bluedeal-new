# 블루딜 운영 점검과 최근 핫딜 감시

Python 3.13과 기존 핫딜 수집기의 Beautiful Soup 설치가 필요합니다. 웹사이트의 Node 프로세스와 독립적으로 실행합니다.

```powershell
python ops/maintenance/run.py
python ops/maintenance/run.py --collect
```

첫 명령은 공개 홈페이지·가격표·핫딜 게시판·버전·가격표 상태 API를 읽습니다. 배포된 커밋의 가격 파일과 운영 API의 해시가 일치할 때만 개별 가격의 실제 확인 시각을 계산합니다. 로컬 개발 파일을 운영 자료로 잘못 판단하지 않습니다. 실행 결과는 `ops/private/maintenance/report.html`, `last-health.local.json`, `history.jsonl`에 저장합니다. 원격 응답 본문이나 쿠키·자격 증명은 기록하지 않습니다. 종료 코드 0은 정상, 1은 재확인 사항, 2는 오류, 3은 다른 점검 실행 중입니다.

`--collect`는 퀘이사존의 허용된 공개 목록 최근 7일을 `ops/private/hotdeal-watch/`에 별도 보관합니다. 6개월 백필 저장소 `ops/private/hotdeal-research/`를 덮어쓰거나 확인 시각을 바꾸지 않습니다. 실행당 최대 20페이지, 요청 간 최소 3초이며 기존 robots 지침·정지 조건을 따릅니다. 페이지 예산만 소진한 경우 다음 실행에서 재개합니다. 차단·파서 오류는 다음 예약 실행에서도 자동 재시도하지 않고 검토 대기로 둡니다. 완료 후 6시간 이내의 중복 실행은 새 수집을 시작하지 않습니다. 장기간 미실행 시 최근 7일 밖의 공백을 모두 메웠다고 주장하지 않습니다.

수집 금액은 과거 게시글 목록 표기이며 실제 현재 판매가가 아닙니다. 출처의 상업적 재사용 조건 확인 전 자동 재게시하지 않습니다. 쿨엔조이의 robots 제한과 뽐뿌의 HTTP 접근 제한은 우회하지 않습니다. 기존 6개월 자료와 최근 감시 자료는 아직 하나의 통합 상품 카탈로그가 아닙니다.

가격·재고는 G마켓·11번가·쿠팡 등 실제 판매처의 동일 옵션에서 별도로 검증해야 합니다. 현재 정확한 상품별 가격을 공급하는 자동 피드는 준비되지 않았습니다. 점검 프로그램은 가격, 가격 확인 시각, 제휴 설정, 게시글, 배포를 바꾸지 않습니다. 보고서는 오래된 가격을 재확인 대상으로 남기며, 누락된 피드를 정상으로 처리하지 않습니다.

단순 네트워크 연결 실패는 `network-paused`로 구분해 다음 예약 실행에서 재개할 수 있습니다. HTTP 401·403·429 및 robots 제한은 검토 대기로 남기며 다시 요청하지 않습니다.

## 일반 프로그램 정기 실행 — 2026-11-20 전환

Windows 작업 스케줄러에 현재 사용자·일반 권한·로그인 상태로 다음 작업을 등록했습니다. 비밀번호를 저장하지 않으며 PowerShell은 숨김 창으로 Python 프로그램을 실행합니다. Codex·모델·API 키를 호출하지 않습니다.

| 작업 이름 | 주기 KST | 실행 내용 |
| --- | --- | --- |
| BLUEDEAL-Maintenance-health | 30분마다 | 공개 경로·버전·가격표·오래된 가격·DB 상태 확인 |
| BLUEDEAL-Maintenance-collect | 매일 09·17시 | 위 점검과 허용된 최근7일 목록 감시 |
| BLUEDEAL-Maintenance-backup | 매일 02시 | 조사 DB 2개와 공개 점검 보고서의 로컬 백업 |

`scheduled.py`는 위 작업을 수행하고 재확인 사항(attention)과 실행 오류(failed)를 구분합니다. `run.py`의 종료1은 스케줄러 실패로 취급하지 않지만 원래 경고는 보존합니다. 동시 실행은 잠금으로 막고, 로그인·네트워크로 놓친 실행은 실행 가능할 때 처리하도록 설정했습니다. 임의 재시도 루프나 접근 차단 우회는 없습니다.

`register_tasks.ps1`은 기본으로 계획만 출력합니다. `-Install`은 예약을 등록하며 같은 이름의 작업이 있으면 덮어쓰지 않습니다. `verify_tasks.ps1`은 명령·일반권한·인터랙티브로그인·중복 방지를 확인하고 등록된 OS 작업을 직접 시작합니다. 2026-11-20 검증에서 health2회/collect1회/backup1회 모두 LastTaskResult=0, AI호출0이었습니다. 이는 수동 Start-ScheduledTask 검증이며 당시 예약 시각의 자연 실행까지 관찰한 것은 아닙니다. 근거는 `ops/private/maintenance/scheduled-migration-verification.local.json`입니다.

기존 Codex heartbeat `automation`은 위 검증 후 PAUSED로 전환했습니다. 이 PC와 Windows 로그인·네트워크가 필요하며 Codex 앱을 켜 둘 필요는 없습니다. PC 종료와 독립적인 24시간 서버 운영은 후속 단계입니다. 장애의 AI 자동 호출은 연결하지 않았습니다.

사용자는 상위 폴더 `블루딜 관리 현황.cmd`를 더블클릭하거나 `ops/private/maintenance/dashboard.html`을 열어 확인할 수 있습니다. 실행별 기록은 `scheduler/runs/`, 작업별 마지막 상태는 `scheduler/last-*.local.json`입니다. 이 데이터는 Git·배포에 포함하지 않습니다.

백업은 `hotdeal-research`·`hotdeal-watch` SQLite와 공개 상태 보고서만 포함합니다. SQLite 온라인 백업으로 WAL의 커밋을 반영하고 저장본을 열어 quick_check와 스키마를 확인합니다. 계정 보관함·환경변수·다른 비공개 자료는 포함하지 않습니다. 원본 DB는 변경하지 않습니다. 보관량 상한1GiB에 닿으면 정리 검토 경고를 남기며 자동 삭제하지 않습니다.

## 통합 상품 검토 목록

수집 예약이 끝나면 `candidate_index.py`가 과거6개월 DB와 최근7일 DB를 읽기 전용으로 합칩니다. 동일 출처+게시글 번호만 중복 제거하며 제목이 비슷한 다른 글은 합치지 않습니다. 겹친 글은 실제 관측 시각이 더 최신인 내용을 선택하고 양쪽 출처·작업·관측 시각을 모두 보존합니다. 파생 목록을 생성한 시각으로 원문·가격 확인 시각을 바꾸지 않습니다.

기존 가격표34개 판매 항목은 별도의 모델 목록으로 정리했습니다. 기존 RAM3쌍의 판매처 중복만 명시적인 목록으로 연결하고, 용량·모듈구성·메모리타입·속도·CL·색상을 포함한 이름이 달라지면 통합을 거부합니다. 2026-11-20 현재31개 내부 모델이며 제조사 SKU 검증 완료를 뜻하지 않습니다.

결과는 `ops/private/catalog-review/report.html`, `summary.local.json`, `baseline-models.local.json`, `candidates.local.json`, `candidate-queue.generated.csv`입니다. 현재 PC후보글600건으로 정리됐으나 고유 검증 상품600개가 아닙니다. 후보의 실제 판매처·선택옵션·현재가·배송비·확인 시각은 미확인으로 남깁니다. CSV는 수집 후 재생성하는 출력물이며, 검증 결과를 입력하는 원본 파일로 사용하지 않습니다. 검증 결과는 별도 기록에 보관해야 합니다.

## 웹 빌드 검증

Windows에서 재현된 Turbopack PostCSS 하위 프로세스 연결 문제를 분리하기 위해 프로젝트의 기본 `npm run build`를 Next.js가 지원하는 `next build --webpack`으로 설정했습니다. 버전 API 두 곳의 package.json 가져오기도 기본 가져오기로 맞춰 webpack 경고를 없앴습니다. 2026-11-20 기본 빌드·TypeScript·린트와 계산/스냅샷 테스트20개, 로컬 HTTP5흐름 및 버전 API2개 검증을 통과했습니다. 브라우저의 로컬 접속 실패·오류 페이지 정책 차단으로 실제 모바일 화면은 아직 검증하지 못했습니다. 운영 배포는 하지 않았습니다.
