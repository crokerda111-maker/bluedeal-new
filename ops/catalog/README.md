## 2026-11-21 상품 전체 엑셀·홈페이지 연결

사용자는 확보 상품 전체를 분류·특징·상세·후기·피드백 관리용 엑셀로 만들고 홈페이지에도 먼저 등록하도록 요청했다. 현재 공개 데이터는 기존 내부 모델 31개와 제조사 목록 373개 항목, 기존 공식 조사 CPU 1개를 연결한 **405개 등록 항목**이다. 모델 274개·출력 옵션 91개·제품군 40개를 구분한다. 전체 국내 시장 SKU를 모두 확보했다는 뜻은 아니다.

`export_site.py`는 원장과 기존 가격 파일을 읽기 전용으로 조회해 허용된 필드만 비공개 중간 자료로 내보낸다. 계정·이동 코드·제휴 식별자·사적인 원본 속성은 복사하지 않는다. 과거 판매처 가격 34개는 별도 관리용 파일에 원래 관측 시각과 함께 남긴다. 공개 상품 데이터에는 현재가·재고·평점·미검토 후기 요약을 만들지 않는다.

```powershell
python -m ops.catalog.export_site
node --experimental-strip-types ops/catalog/prepare-public.mjs
npm run test:catalog
```

`prepare-public.mjs`는 기존 부품 조사 자료를 연결하고 안정적인 상품 ID·관리번호와 내용 해시를 부여해 `src/content/products/catalog.json`을 만든다. 웹 서버는 이 공개 자료만 사용하며 비공개 SQLite·수집 원문·엑셀을 읽거나 업로드하지 않는다. `/prices`의 통합 검색과 `/prices/[category]`의 부품별 필터로 상품·가격을 함께 찾는다. 구 `/products` 목록은 검색 조건을 보존해 영구 이동하며 `/products/[id]` 상세 주소는 유지한다. 미확인 사양은 별도로 검색할 수 있고 제품명만으로 호환성을 추정하지 않는다. 미완성 조사 단계인 상품 화면은 검색엔진 제외 상태를 유지한다.

상품 상세의 수정·추가 요청은 서버가 실제 등록된 상품을 대조한 뒤 이름·관리번호·상품 URL을 채운다. 기존 운영자 전용 비공개 문의 흐름을 사용하며 방문자에게 비밀번호나 비공개 문의 열람 권한을 부여하지 않는다. 실제 운영 글 자동 작성이나 기존 문의 조회·추출은 하지 않는다.

관리 엑셀은 웹 저장소 밖 `outputs/bluedeal-products-20261121/`에 생성한다. 관리현황·상품관리·피드백·판매처기록·자료근거 다섯 시트이며 관리번호와 홈페이지 링크를 공유한다. 노란 입력 영역은 편집용이고 사이트에 자동 반영되지 않는다. 빈칸/요청 상태 변경·상품명 연결·집계 재계산, 필터·드롭다운·고정창과 XLSX 내보내기를 확인한다. 사용자가 수정한 파일은 생성 당시 해시와 달라지면 다시 덮어쓰지 않는다. 운영 반영 상태는 정확한 상품 해시/항목 수의 공개 검증 기록이 있을 때만 표시한다.

로컬 읽기 전용 확인은 `node ops/tests/catalog-http.mjs`를 사용한다(기본 `http://127.0.0.1:3100`). 405개 상세·목록·필터·빈 결과·잘못된 상품 404·상품별 수정 요청의 초기 문맥을 확인하며 글을 제출하지 않는다.

2026-11-20 첫 구현. 현재 범위는 **비공개 SQLite 원장 초기화, 제조사 공식 목록의 첫 수집·가져오기, 검증된 단일 상품의 명시적 할인 조합 계산**이다. 실제 판매처 수집 어댑터, 행사 원문 해석기, 전체 시장 목록, 장바구니 최적화, 운영 게시 연결은 아직 구현하지 않았다. 설계와 조사 근거는 [평가·수집 설계](../assessment/README.md)를 따른다.

결과는 `ops/private/catalog/discovery.html`, `discovery-summary.local.json`, 같은 `catalog.sqlite3`의 `manufacturer_sources`/`manufacturer_items`/`manufacturer_item_observations`에 있다. 원문 스냅샷과 해시는 `source-probes`에 보존한다. 다른 출처·옵션을 이름 유사성으로 합치지 않으며 원본 관측 시각·이력을 보존한다. 다시 해석해도 시각을 새로 만들거나 운영자가 입력한 국내 유통/부품 연결 상태를 덮어쓰지 않는다.

```powershell
python -m pip install -r ops/catalog/requirements.txt
python -m ops.catalog.probe_lists
python -m ops.catalog.discovery
```

`probe_lists`는 등록 출처 중 결과가 없는 곳만 한 번 확인한다. 이미 확보하거나 접근이 중단된 출처는 자동 재요청하지 않는다. 새로 확인할 출처는 `--source`로 제한할 수 있다. 네트워크 허용이 필요하며 공개 목록 외 로그인·계정·상품 상세 대량 요청·운영 게시를 수행하지 않는다. `discovery`는 저장본만 해석하는 오프라인 명령이다. 원장 초기화 후 실행하며 손상된 해시는 가져오기 전에 거부한다. 빈 결과/구조 변경은 검토 상태로 기록하고 기존 자료를 삭제하지 않는다. 이 프로그램은 아직 모든 제조사의 페이지를 순회하거나 정기 갱신하지 않는다.

다음 범위는 CPU·메인보드·RAM·GPU·파워·SSD/HDD·케이스·쿨러의 주요 제조사 목록이다. 차단 출처는 중단 상태를 보존하고 이용 가능한 다른 제조사·공식 배포 자료를 조사한다. 분류별 국내 유통과 제조사 품번/리비전 확인 → 동일 제품 병합 → 여러 판매처·현재가·행사·제휴 연결 순으로 확장한다. 현재 쿨러 항목 수가 많다는 이유로 CPU/보드/RAM의 누락을 완료로 처리하지 않는다.

첫 명령은 기존 가격 파일과 `ops/collector/catalog.json`을 읽어 `ops/private/catalog/catalog.sqlite3`를 만든다. 세 개의 기존 RAM 판매처 쌍만 기존 명시적 별칭·옵션 대조를 거쳐 연결한다. 초기 자료는 내부 모델 31개/판매 상품 34개이며 제조사 품번 검증은 별개다. 재실행해도 기존 검증 필드와 근거 시각을 덮어쓰지 않는다. 판매자·옵션·판매 주소 충돌은 검토 오류로 중단한다. 과거 가격, 이동 코드, 제휴 식별자, 계정 정보는 가져오지 않으며 새 가격 관측과 혜택도 생성하지 않는다.

원장은 부품/변형/판매 상품/항목별 근거/가격 관측/혜택 버전/본체 구성/서버 제휴 참조를 분리한다. 최초 가져온 사양은 `curated-unverified`, 실제 관측·제조사 검증 시각은 빈값이다. 원장에 URL이 있다는 이유로 제조사 확인이나 제휴 승인이 완료되지는 않는다. 후보 게시글 600건은 별도 검토 목록에 남겨두고 제품으로 자동 확정하지 않는다.

현재 DB는 Git 제외 대상이고 초기화 원본으로 재생성 가능하다. Windows 예약 작업에는 아직 연결하지 않았으며 기존 두 조사 DB의 자동 백업 범위에도 아직 포함되지 않는다. 운영자가 이 DB에 새 검증 자료를 저장하기 전 백업 범위 확장을 함께 해야 한다.

## 계산 입력 계약

`pricing.quote(offer, rules, now=시간대있는datetime, context=선택조건)`은 수집기가 검증한 입력만 계산한다. 함수 자체가 원문을 읽거나 입력의 진위를 확정하지 않는다.

- Offer: 판매상품·변형·판매자 ID, 원화 상품가, 선택 배송지에 확인된 배송비, 수량 1, 재고, 옵션 검증, 공개 근거 URL, 직접/공식 API 출처, **원본 실제 관측 시각**과 검증 시각이 필요하다. 캐시·24시간 초과 관측·미확인 옵션/배송/재고·비원화/다수 수량은 결제 예상가를 생성하지 않는다. 재다운로드 시각으로 관측 시각을 새로 쓰면 안 된다.
- Rule: 정확한 판매상품/변형/판매자 범위, 혜택 종류, 고정금액/비율, 기준금액, 상한, 시작/배타적 종료 시각, 검증된 원문/조건, 적용 순서, 양방향 중복 가능 목록, 자격 조건, 주문/일/월 이용 한도가 필요하다. 비율은 정수 basis points(1000 = 10%)다. 단위 절사와 절사 순서는 확인한 규칙만 넣는다. 현재는 원 단위/10원 단위 내림 및 상한 적용 전 절사만 지원하며 다른 규칙은 추가 구현·검증 전 계산하지 않는다.
- 자격은 카드사·카드 종류·간편결제·회원·앱·쿠폰 보유·첫 구매·실적·할부 조건만 지원한다. 지원하지 않는 조건을 삭제해서 계산하면 안 된다. 미입력 조건, 미확인 중복, 일/월 잔여 횟수·금액 미확인은 해당 혜택을 제외하고 사유를 남긴다. 카드번호·계정·인증정보는 입력하지 않는다.
- 할인 기준과 최소 구매금액 기준은 각각 원래 상품가/직전 할인 후 상품가 중 명시한다. 배송비 포함 최소금액, 배송 할인, 묶음 주문, 세금/환율 등은 현재 계약 밖이다. 지원하지 않는 행사는 확정 가격으로 변환하지 않는다.
- `ordinary_delivered_krw`와 해당 선택 조합의 `scenario_payment_krw`를 구분한다. 청구할인/캐시백은 `post_payment_benefits`, 적립은 `points_benefits`에 따로 남긴다. `checkout_confirmed`는 항상 false이며 최종 장바구니 확인을 대체하지 않는다.
- 이 함수는 **주어진 한 조합**을 계산한다. 가능한 모든 쿠폰·카드를 탐색한 최저가나 여러 부품의 최적 주문을 보장하지 않는다. 다른 조합/상품 간 일·월 한도 공유와 최적 주문은 후속 별도 단계에서 관리한다. 본체 부품별 조건부 최저가를 단순 합산하면 안 된다.

테스트 가격은 모두 `.invalid` 가상 출처다. 상품 100000원·쿠폰 10000원·쿠폰 후 카드 10%(상한 5000원)·배송 3000원 조합은 조건 확인 시 88000원이다. 실제 상품이나 현행 행사로 게시하지 않는다.

## 실제 수집 연결의 다음 순서

1. 제조사 공식 목록에서 품번·변형·국내 유통 여부를 확인하고 항목별 근거를 저장한다. 다나와는 제품 발견에만 사용한다.
2. G마켓/11번가 대표 표본으로 이용 가능한 공식 피드와 허용된 판매 상세를 대조한다. 상품가·옵션·판매자·배송·재고 중 빠진 필드를 명시하고 가격 관측을 검토 상태로 저장한다.
3. 상품 혜택 상세/행사 원문에서 종료일·중복·상한·조건을 확보하고 검증된 규칙으로 변환한다. 개인별 쿠폰·실적·잔여 한도는 조건부로 유지한다.
4. 실제 판매 페이지와 계산을 대조한 뒤 정기 수집, 변경·만료 감지, 공개 화면 및 공식 제휴 경로를 연결한다. 채널마다 확보 필드/누락률을 집계한다.

브라우저 보안/robots/401·403·429/CAPTCHA 차단은 우회하지 않는다. 신규 계정·권한·유료 피드·계약은 구체적 대상과 조건을 확인한 뒤 진행한다.
